## 3. PDF structure checks

* Metadata: `Producer=Odoo`, `Creator=Odoo`; no XMP; not encrypted; no JavaScript/OpenAction.
* Annotations: two `/Link` to `https://sipanelco.ir` (company footer).
* Embedded files: one — `SI-26_312_ubl_bis3.xml` (Peppol BIS3 order, generated by the native `sale_edi_ubl` module for every quotation PDF). Reviewed in full: parties, addresses, contact e-mail/phone of the seller, order id, customer reference, validity, line descriptions (the customer notes), quantities, prices, allowances (5 % discount), taxes, totals, `SellersItemIdentification/ID` = anchor product internal reference, `Item/Name` = anchor product name. **No internal-only component, cost, margin, analytic or audit data.** Finding F-02: anchor product names/references are customer-visible through this channel; master data must be named accordingly (the archived demo master `SIPANEL-PT Gutter run (anchor)` would have been visible).
* Fonts: as served today DejaVu/Nimbus (D-01); with D-01 corrected IRANSans subset only.

## 4. Portal source checks

* No HTML comments, no inline JSON state, no `sipanel_*` field names in the page.
* SIPANEL-specific attributes: `data-sipanel-revision-id`, `data-sipanel-seal-hash` on the optional line's quantity widget only (binding for GAP-S04; the hash is SHA-256 of customer-visible payload, not a credential).
* Chatter: only public messages would be shown; the internal note and the two internal notifications ("Sales Order created", "Quotation viewed by customer …") are not rendered.
* Frontend assets: `sipanel_sale_scope/static/src/interactions/sipanel_update_line_button.js` only forwards the two binding attributes.

## 5. Information exposed by design (not defects)

* Salesperson display name (`Taleghani`) and stored signature/stamp image in the PDF signature block and portal (`sale_shamsi_report` layout, standard Odoo behaviour).
* Company footer address/phones/website.
* Order-level customer note and line notes (customer-authored content).

## 6. Bundle hygiene

`grep` over the final report directory for both live tokens, `db_password`, `admin_passwd`, `PRIVATE KEY`, `session_id=`: no hits. The scratch `tokens.json` (mode 600) was deleted at the end of the run. No database dump, filestore or configuration file is included; the recovery point stays outside the repository under root-only permissions.
